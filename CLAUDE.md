This file provides repository guidance for coding assistants.

## Project

Personal Jekyll site for Guillermo Carrasco, an NYC-based yoga teacher. It is deployed to `guillermoyoga.com` through GitHub Actions. The stack is intentionally lean: Jekyll 4, Sass, and dependency-free JavaScript.

## Commands

```bash
make install          # install gems with the pinned Ruby toolchain
make site             # build _site locally
make check            # build and validate generated HTML/internal links
make serve            # build and serve in Docker with LiveReload
make serve-detached   # run the Docker server in the background
make stop             # stop the Docker service
make logs             # follow Docker logs
make shell            # open a shell in the Jekyll container
```

Ruby is pinned in `.ruby-version`. Docker uses the same version. CI builds the locked bundle before deploying, so local, CI, and production use the same Jekyll/Sass stack.

## Architecture

- `default.html` is the document shell. It includes the head, accessible navigation, main landmark, footer, scripts, and production-only analytics.
- `page.html` and `post.html` render hero sections. A `.jpg` `background` value expects a matching `.avif` asset, which is preloaded and preferred through CSS `image-set()`.
- `assets/main.scss` loads `_sass/styles.scss` with Sass modules. Design tokens are declared in `:root` at the top of `_sass/styles.scss`.
- `assets/scripts.js` handles the progressively enhanced mobile navigation and asynchronous Formspree submission.
- SEO metadata is generated by `jekyll-seo-tag`; feed, pagination, and sitemap behavior come from their Jekyll plugins.

## Authoring

- Add journal entries at `_posts/YYYY-MM-DD-slug.md` with `layout: post`.
- Use `relative_url` for generated URLs and Jekyll's `link` tag for known source files.
- Escape front-matter values when rendering them into HTML attributes or text.
- Run `make check` before committing.
